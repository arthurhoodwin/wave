# Обновления Wave

## Переход на маленькие пакеты

**Beta 5 устанавливается один раз через EXE.** В ней появляется загрузчик файловых обновлений `WAVEUPD2`. Beta 4 и более ранние версии понимают только старый пакет с установщиком внутри. Поэтому у переходной Beta 5 нет публичного `.waveupdate`: такой файл нельзя было бы применить старым клиентом.

Начиная со следующего выпуска пакет содержит изменённые блоки файлов, новые файлы и перечень удалений. Неизменённые файлы Electron не скачиваются заново. Даже внутри изменённого `Wave.exe` и `app.asar` повторяющиеся блоки берутся из установленной сборки; новые данные сжаты Brotli. Полный EXE остаётся для первой установки, смены основы и восстановления.

Пакет относится к **одной точной исходной версии**. При пропуске нескольких выпусков или изменении файлов вручную используйте полный установщик. Приложение не накладывает патч на неподходящую основу. Канал GitHub в настройках по-прежнему проверяет стабильный Latest; Beta импортируется вручную.

## Исправление ASAR в Beta 7

Опубликованный патч Beta 6 не применим старым загрузчиком Beta 5: обычный Electron fs воспринимает app.asar как виртуальный каталог. Совпадение всех 77 реальных файлов это не исправляет. В Beta 7 file-update и UpdateManager используют общий disk-fs.cjs: original-fs в Electron, node:fs в обычном Node. Никакие проверки подписей/хешей не ослаблены.

Переход **Beta 5/6 → Beta 7** выполняется через EXE либо полный `.waveupdate` старого формата. `updateMode: "legacy"` обозначает этот восстановительный выпуск. Используйте CLI с EXE в качестве входа, не каталогом. Старый загрузчик способен проверить и запустить такой пакет. Это разовая полная загрузка; со следующего выпуска возвращается updateMode delta.

Обязательный gate: `npm run test:updates-electron`. ASAR проверяются именно в Electron; помощник запускается после завершения тестового Electron, иначе открытый архив может быть заблокирован. Подробности — в TESTING.md.

## Сборка

1. Сохраните предыдущий `dist/win-unpacked` вне каталога новой сборки. Это точная основа, включая `Wave.exe`, `app.asar` и распакованные ресурсы. Не используйте рабочую установку пользователя.
2. Обновите `version`, `releaseVersion`, `build.buildVersion`, имя EXE и подпись версии интерфейса. После переходной Beta 5 задавайте `updateMode: "delta"`.
3. Выполните `npm test`, затем `npm run dist`.
4. Создайте файловый пакет:

```powershell
node scripts/package-update.cjs dist/win-unpacked dist/Wave-VERSION.waveupdate VERSION $env:WAVE_SIGNING_KEY C:/builds/previous PREVIOUS_VERSION
```

Скрипт сверяет версии с package.json внутри обоих ASAR. Путь к закрытому ключу передаётся переменной; сам ключ не публикуется. Ed25519-ключ должен соответствовать `build/update-public.pem`. Запись файла назначения выполняется только в новый файл.

Для старого формата инструмент по-прежнему принимает путь к EXE вместо каталога и без двух последних аргументов. Это полноценный установщик, а не маленький патч. Старые опубликованные пакеты не переписываются.

## Формат и применение

`WAVEUPD2\n`, uint32 LE длины envelope, JSON `{payload,signature}`, затем Brotli-данные. Подпись Ed25519 покрывает точные байты UTF-8 payload: product, arch, version, baseVersion, kind=files, bytes, sha512. Сжатые данные содержат ограниченный индекс и новые блоки. Индекс описывает исходные и конечные размеры/SHA-512 и операции копирования/добавления блоков. Для удалённого файла конечный hash равен null.

Перед подготовкой проверяются подпись, размер, SHA-512 пакета, исходная версия и все известные файлы основы. Абсолютные пути, `..`, ADS, специальные имена Windows, регистровые дубликаты и junction/symlink внутри пути отклоняются. Размер распакованного блока данных ограничен 512 МиБ; индекс — 1 МиБ, списки — 4096 записей. Готовые файлы повторно сверяются с подписанными конечными SHA-512.

Подготовка выполняется в `updates-v1/patch-UUID`, не в каталоге установленной программы. Сохраняются прежние изменяемые файлы и обратный план для отката. История планов и их контрольных сумм защищена Windows safeStorage. Загрузчик не исполняет код из патча.

После отдельного подтверждения помощник ждёт завершения Wave, ещё раз проверяет план, основу и подготовленные файлы. Затем заменяет только перечисленные файлы, добавляет новые и удаляет явно перечисленные устаревшие. При обрабатываемой ошибке записи уже заменённые файлы возвращаются из временной резервной папки. При успехе Wave запускается заново. Если восстановление само завершилось ошибкой, резервная папка не удаляется.

Это не атомарная замена всего каталога при отключении питания. Внезапное завершение помощника или выключение Windows в середине записи могут потребовать полного установщика. Папка `.wave-transaction-*` содержит резервные файлы и журнал; не удаляйте её до восстановления. Данные пользователя и музыкальные файлы не входят в патч.

## Откат и восстановление

В настройках предлагается ближайшая меньшая сохранённая версия. Для файлового отката проверяется точная версия-источник и текущее дерево файлов; обратный план восстанавливает прежние файлы и удаляет добавленные. Сохранённые старые EXE остаются поддерживаемым способом отката. Автоматического отката по аварии нет.

Если приложение не запускается, завершите его и запустите полный установщик нужной версии из GitHub Releases. Не удаляйте профиль ради переустановки. Профиль `%APPDATA%\wave-vk-research-client` содержит чувствительные данные сеанса VK: не публикуйте его в issues.

Результат установки — `updates-v1/last-install.json`: стадия, числовой код и время. Код 5 означает повреждённый план/установщик, 7 — ошибку помощника. Данные коллекции туда не записываются. `session-health.json` фиксирует чистое завершение и позволяет предложить восстановление при следующем старте.

## Публикация и порядок релизов

В репозитории хранится один `releases/LATEST.md`. Создайте и отправьте тег, проверьте Windows CI, подготовьте SHA256SUMS.txt для публикуемых артефактов, затем `npm run release:check` и `npm run release -- --draft`.

Для обычного выпуска нужны EXE, `.waveupdate` и SHA256SUMS.txt. Для переходного `updateMode: "bootstrap"` нужны EXE и SHA256SUMS.txt. После загрузки сверяйте digest каждого GitHub asset с локальным SHA-256 и **завершайте публикацию черновика**. Старые забытые черновики отображаются владельцу перед опубликованными выпусками. Для Alpha/Beta/RC сохраняйте prerelease и `--latest=false`. Стабильный Latest назначается отдельно. Теги и старые assets ради сортировки не пересоздаются.

## Локальные артефакты

```powershell
node scripts/clean-artifacts.cjs
npm run artifacts:clean
```

Первая команда показывает план, вторая удаляет устаревшие Wave-Setup-*.exe, их blockmap и Wave-*.waveupdate непосредственно из `dist/`. Сохраняются файлы текущей версии; каталоги, исходники, ключи, профили и опубликованные файлы GitHub не затрагиваются. `dist/win-unpacked` текущей версии — основа следующего патча, его нужно сохранить до следующей сборки.

Ed25519-подпись пакета — не Authenticode Windows. Сертификат Authenticode не настроен. Независимая установка на другом Windows-ПК остаётся ручной проверкой. Текущие прогоны и ограничения — [VALIDATION.md](VALIDATION.md).
