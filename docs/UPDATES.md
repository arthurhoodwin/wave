## Подготовка

1. До пересборки сохранить предыдущий win-unpacked **целиком** вне dist — точную основу патча. Не использовать установленный пользовательский каталог вместо проверенной основы.
2. Согласованно обновить package.json/package-lock.json, releaseVersion/releaseChannel, buildVersion, artifactName и видимую версию в ui-polish.js.
3. Заменить releases/LATEST.md. Первая строка строго `# Wave VERSION`, как требует release.cjs. Остальное — полное понятное пользователю описание, без чисел тестов и внутреннего протокола.
4. Выполнить:

```powershell
npm test
npm run test:updates-electron
npm run dist
```

5. Подготовить нужные подписанные пакеты и SHA256SUMS.txt. EXE собирается без обязательного Authenticode; Ed25519-подпись обновления — отдельный механизм.

## Пакетирование

`WAVE_SIGNING_KEY` — путь к приватному PEM, не его содержимое. Скрипт сверяет его с build/update-public.pem. Приватный ключ не помещать в Git, dist, профиль, отчёт или снимок. Для форка нужна собственная пара ключей и идентичность продукта.

Полный пакет (legacy, нужен только при отдельном решении о совместимости):

```powershell
node scripts/package-update.cjs dist/Wave-Setup-1.1.0.exe dist/Wave-1.1.0.waveupdate 1.1.0 $env:WAVE_SIGNING_KEY
```

Канонический файловый пакет 1.1.1 от сохранённой Stable 1.1.0:

```powershell
node scripts/package-update.cjs dist/win-unpacked dist/Wave-1.1.1.waveupdate 1.1.1 $env:WAVE_SIGNING_KEY C:/builds/1.1.0/win-unpacked 1.1.0
```

Для следующего выпуска заменить версии/пути на фактические. Каталоги обязаны содержать настоящие ASAR с заявленными версиями, скрипт это проверяет. Файл назначения должен быть новым. При смене runtime/основы размер патча может увеличиться; не обещать постоянный размер.

## Форматы и проверка

Оба формата начинаются magic и uint32 LE длины JSON-envelope `{payload,signature}`. Ed25519 подписывает точные UTF-8 байты payload. В нём product app.wave.vk, arch x64, версия, размер и SHA-512 тела. Файловый пакет дополнительно содержит kind=files и точную baseVersion.

- **WAVEUPD1:** тело — полный EXE; после проверки извлекается и запускается штатным помощником.
- **WAVEUPD2:** тело — Brotli с ограниченным индексом и новыми блоками. Содержит операции копирования неизменившихся блоков, добавления данных и удаления файлов. Новые/конечные файлы сверяются с SHA-512.

Границы: пакет до 1 ГиБ; распакованные данные V2 до 512 МиБ; индекс до 1 МиБ; списки до 4096 записей. Относительные пути проверяются против выхода из каталога, ADS/специальных имён, регистровых дубликатов и ссылок. Проверяются перечисленные файлы основы, не произвольные дополнительные файлы установщика.

**ASAR:** в Electron обычный fs возвращает app.asar как виртуальный каталог. update-manager/file-update используют disk-fs.cjs → original-fs; в Node — обычный fs. Нельзя лечить ошибку основы отключением подписи/хеша. Этот дефект старых Beta 5/6 исправлен в Beta 7.

## Применение и откат

Подготовка идёт в updates-v1 вне каталога программы. Сохраняются прежние изменяемые файлы, обратный план и защищённая история. После отдельного разрешения установки Windows-помощник ждёт выхода приложения, повторно проверяет план/файлы и заменяет перечисленное. Запущенный Electron может удерживать ASAR; стадирование и применение — разные фазы.

При обычной ошибке записи помощник возвращает уже заменённые файлы. Если восстановление само завершилось ошибкой, резервная папка не удаляется. **При отключении питания посреди замены атомарность всего каталога не гарантируется**; восстановление — полным установщиком. Автоматического отката по аварии нет.

Для файлового отката проверяются точная текущая версия и основа обратного плана. История также поддерживает сохранённые EXE. Если программа не запускается, использовать установщик нужной версии из GitHub или локальной папки установщиков; профиль ради этого не удалять.

- updates-v1/last-install.json: стадия, код, время. Без коллекции; код 5 — проверка файла, 7 — ошибка помощника.
- session-health.json: признак чистого завершения. Предложение восстановления не доказывает причину сбоя.
- Кэш установщиков: `%LOCALAPPDATA%/Wave/installers`. NSIS использует техническую npm-версию, история обновлений — публичную releaseVersion.

История и профиль защищены safeStorage. Отдельный Electron с другим userData может не расшифровать историю рабочего профиля. Не извлекать ключ профиля и не заменять защищённую историю пустой ради автоматизации; использовать штатное приложение либо проверенный полный EXE. Stable на основном ПК установлена полным EXE, а маленький патч проверен отдельно на стенде.

## Публикация

```powershell
npm run release:check
npm run release -- --draft
```

Перед этим создать/отправить тег vVERSION и проверить Windows CI точного коммита. В черновике дождаться всех assets, сверить каждый GitHub digest с локальным SHA-256 и текст с LATEST.md. Опубликовать только после успешных gates. Alpha/Beta/RC: prerelease, latest=false; Stable: prerelease=false и явный Latest. Не изменять уже опубликованные теги/бинарники; исправление выходит следующим номером.

Число assets зависит от режима: обычный выпуск — EXE/пакет/SHA256SUMS, bootstrap — EXE/SHA256SUMS, extraUpdateBase добавляет отдельный малый пакет. Не оставлять старые релизы в черновиках: они отображаются владельцу выше опубликованных и создают впечатление неправильного порядка.

Исторические номера 1.0.61/62, четырёх-/пятичастные фиксы и suffix alpha/beta/rc поддерживаются compare. Новые обычные номера — SemVer major.minor.patch; не создавать 1.0.61 как исправление 1.0.6.

## Рабочие договорённости

- Готовые версии после публикации/проверок устанавливать на ПК владельца в рамках его действующего поручения. Закрывать приложение штатно, не прекращать активную работу force-kill без отдельного основания.
- Если обязательная проверка разрешений отклонила действие, не обходить её: объяснить причину и получить требуемое подтверждение. Сам файл документации не является новым согласием пользователя.
- Разрешение обновить приложение не разрешает лайки, удаление музыки или другие записи в VK. Такие проверки владелец оставил себе.
- Пользовательские release notes и инженерные отчёты не смешивать. Текущие результаты — [VALIDATION.md](VALIDATION.md), дальнейшие проверки — [ROADMAP.md](ROADMAP.md).

## Локальная уборка

```powershell
node scripts/clean-artifacts.cjs
npm run artifacts:clean
```

Первая команда — план. Вторая удаляет устаревшие Wave-Setup EXE/blockmap и Wave-*.waveupdate непосредственно в dist, сохраняя текущую версию и extraUpdateBase-пакет. Источники, подписи, профиль, ключи и файлы GitHub не затрагиваются. Сохранять текущий win-unpacked как основу следующей сборки. Перед иной рекурсивной уборкой проверять абсолютный целевой путь и его принадлежность рабочему каталогу.

## Возобновляемая публикация

`npm run release -- --draft` сначала проверяет локальные файлы/SHA256SUMS, создаёт либо находит черновик, загружает малые assets и затем EXE. Уже загруженные файлы принимаются только при совпадении digest и размера. Неполный asset черновика можно передать повторно; несовпадающий завершённый файл автоматически не заменяется. После ошибки тот же вызов продолжает передачу, пересборка не требуется. Публичные релизы не меняются.

HTTP/1.1 включён для gh-процессов этого скрипта, проверка TLS остаётся включённой. Таймаут по умолчанию300000мс; переменная `WAVE_RELEASE_UPLOAD_TIMEOUT_MS` допускает10000–1800000мс. Без `--draft` публикация выполняется только после проверки всех файлов. CI на теге не дублирует main: проверяйте успешный запуск именно на релизном SHA.
