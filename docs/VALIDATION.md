## 1.1.1.1 · Исправление нагрузки индикатора

Публичная версия 1.1.1.1, npm SemVer 1.1.1+hotfix.1, Windows FileVersion 1.1.1.301. Отдельный hotfix не занимает запланированную функциональную версию 1.1.2.

Причина: бесконечная плавная CSS-интерполяция четырёх полосок. На изолированном offscreen Electron-стенде без аудио/VK последовательность static → smooth → steps → static дала 0 → 60 → 12 → 0 paint events/с. Интервалы — 6 секунд; наличие полосок и computed animationName проверялось, отключение выполнялось CSSOM-свойствами (inline style element блокируется CSP). Это измерение стенда, не процент загрузки GPU рабочего окна и не обещание уменьшить общую нагрузку ровно в пять раз. CPU-метрики GPU-процесса не равны показателю GPU в диспетчере задач.

Исправление ограничивает интерполяцию steps(4,end); исходные длительности, фазы, static/reduced-motion и остановка вне видимой области не меняются. Локальный исходный отчёт — work/perf-wave111.json. После изменения CSS повторный замер фактической сборки исходников: static 0 → current 12,17 → static 0 paint events/с. Пройдены 309 Node-тестов и отдельный Electron ASAR-гейт. Подписанный файловый пакет от точной 1.1.1 — **147851 байт**. Применение и откат на изолированной копии: все 77 файлов совпали с новой/старой основой. Проверены пакетный releaseVersion и итоговый CSS в ASAR; EXE FileVersion 1.1.1.301. Тег v1.1.1.1, коммит 349c009c51cf02da8ab5722770cd5bdb59d5fa09: Windows CI тега [40152324342](https://github.com/arthurhoodwin/wave/actions/runs/40152324342) и ветки [40152324208](https://github.com/arthurhoodwin/wave/actions/runs/40152324208) прошли с первой попытки. ## Решение о Stable · 25 октября 2026

Владелец решил выпустить 1.1.0 на функциональной основе RC 1, оставив дополнительные натурные проверки на будущее. Сценарии настоящего VK, маленького пакета на рабочей установке и независимого Windows-ПК не объявляются выполненными. Ниже сохранены исходные результаты, включая ограничения стенда.

Stable изменяет номера/канал выпуска, оформление документации и две согласованные детали интерфейса: настройки/восстановление доступны через профиль, мини-плеер перенесён к громкости. Для совместимости с прежней 1.0.9.9.1 канонический Wave-1.1.0.waveupdate содержит полный установщик; отдельный файловый пакет строится от точной RC 1. Проверки сборки, подписи и CI выполняются до публикации. Локальная установка выполнена после публикации и успешного CI; результат ниже.

Повторно прошли 300 Node.js-тестов и Electron ASAR-гейт. Все 103 упакованных исходных файла совпали с рабочим деревом. На изолированной копии подписанный патч RC 1 → Stable (215 354 байта) применён и откачен: все 77 файлов совпадают с целевой и исходной сборками. Код загрузчика из тега 1.0.9.9.1 принял и проверил подпись полного пакета 1.1.0; запуск NSIS в этой проверке заменён callback. Это не установка на независимом ПК.

## Исправление Beta 7

Подтверждён пользовательский отказ Beta 5 → Beta 6. Все **77 установленных файлов** совпали по размеру и SHA-512 с основой опубликованного патча; данные приложения не изменялись. Отдельный Electron 45 без окон воспроизвёл причину: node:fs.stat(app.asar).isFile() = false, original-fs.stat(app.asar).isFile() = true, original-fs читает 34 700 565 реальных байт. Старый verifyBase выдал ровно пользовательское сообщение.

Исправлен доступ к диску через original-fs в Electron. Проверка подписи, точной версии и SHA-512 остаётся обязательной. Для настоящего несовпадения ошибка содержит относительное имя файла.

**Прежняя проверка патча Beta 6 на Node.js была недостаточной**: она не воспроизводила Electron ASAR и не подтверждала работоспособность импорта из установленной Beta 5. Соответствующее утверждение о применимости маленького пакета отозвано. Ниже оставлены исторические результаты стенда с этой оговоркой.

Новый обязательный прогон `npm run test:updates-electron`: настоящие искусственные ASAR, подпись, стадирование в Electron, завершение процесса, замена Windows-помощником, новый Electron, подготовка отката, завершение процесса и обратная замена. Сверяются точные байты, подмена архива отклоняется. Прогон проходит; добавлен в оба Windows workflow. 290 Node.js-тестов также проходят.

Собранный полный пакет Beta 7 дополнительно принят **настоящим кодом загрузчика из установленной Beta 5**, запущенным в отдельном Electron с искусственным каталогом обновлений; запуск NSIS заменён callback-журналом. Исправленный загрузчик из **упакованной Beta 7** также успешно подготовил исходный маленький пакет Beta 6 на тех же неизменённых файлах Beta 5 — воспроизводимый отказ старого загрузчика исчез. Все 102 упакованных исходных файла сверены с рабочим деревом.

На рабочей установке выполнено только чтение файлов. Рабочее окно, профиль и VK не управлялись. Полная установка NSIS и ручная проверка на отдельной машине по-прежнему не выполнены. Для обхода неисправного старого загрузчика Beta 7 распространяется полным EXE и подписанным полным `.waveupdate` старого формата. Размер этого восстановительного пакета не является размером будущих файловых патчей.

## Ручная проверка VK владельцем

1. Откройте Главную логотипом. Проверьте доступные подборки и переход из карточки к настоящему списку.
2. На тестовой песне снимите лайк нижней кнопкой и сразу верните. Проверьте сердце в плеере и строке, затем обновите «Мне нравится» и перезапустите приложение.
3. Добавьте из нижней панели другую песню, которой ещё нет в коллекции. Проверьте результат после обновления списка.
4. Если удалённую собственную копию уже нельзя восстановить, приложение предлагает найти песню в поиске; оно не отправляет новую запись наугад.

Повторить на других аккаунтах и другом Windows-ПК, когда они доступны. До этого не отмечать соответствующие пункты роадмапа выполненными.

## Примечание к исправлению лайка

Путь собственной удалённой копии проверен по коду и синтетическому сценарию. Назначение `audio.restore` описано в [документации VK.NET](https://vknet.github.io/vk/audio/restore/); это описание старой версии API, не доказательство ответа текущего VK. Поэтому исправление не объявляется натурно подтверждённым до ручного прогона владельцем.

### Финальные панели Stable

По последнему запросу владельца убраны отдельные настройки и восстановление из верхней панели. Доступ остаётся через профиль, включая состояние без входа: из него доступна кнопка входа в VK. Мини-плеер перенесён в player-right перед громкостью. При ширине до 850 px нижняя правая группа получает собственную строку, поэтому кнопка не пропадает при масштабе 200%.

В скрытом демонстрационном renderer проверены отсутствие recovery-open, скрытая отдельная кнопка настроек, открытие диалога профилем и доступный вход без авторизации, размещение мини-плеера у громкости и его видимость при 1440/1100/320 px и 200%. Axe без нарушений. В CI выявлена медленная инициализация PowerShell в файловом стенде; ограниченный срок запуска помощника увеличен только для этих интеграционных случаев, ошибки spawnSync не принимаются за ожидаемый отказ. Сравнения файлов/отката сохранены.

### Фактическая установка Stable

25 октября 2026 версия 1.1.0 опубликована как обычный релиз и назначена GitHub Latest. Окончательное описание GitHub совпало с releases/LATEST.md; четыре опубликованных файла сверены с локальными SHA-256.

По действующему поручению владельца обновлять готовые версии Stable установлена поверх RC 1 полным проверенным EXE. Прежний Wave закрылся обычным CloseMainWindow, без force-kill; NSIS завершился кодом 0. Все 77 установленных файлов совпали со сборкой. В установленном package.json — version/releaseVersion 1.1.0 и releaseChannel stable; Windows FileVersion — 1.1.0.300. Новый главный процесс имеет окно и отвечает. Профиль, cookies и музыкальные файлы вручную не изменялись.

Маленький пакет RC 1 → Stable на рабочем ПК не применялся; его результат остаётся результатом изолированного стенда. Дополнительные натурные проверки остаются отложенными согласно решению владельца.
