## 1.1.8 · Управление коллекцией и подписки

Последний интегрированный сценарий использовал готовый VkProvider.mutate + новый collection-management, включая collectionDetails сохранённой копии и возвращение к оригиналу. finalArtistRestored=true, finalListsRestored=true; прямого чтения cookies/копирования профиля или CDP в пользовательский renderer не было. Wave закрывался обычным способом и возвращался после диагностики. [Контракты, статический REA и ограничения](VK-COLLECTION-CONTRACTS.md).

14 новых Node-сценариев покрывают ownership/права, сохранённую identity, повтор, неподтверждённый результат, отсутствие повторного write, смену аккаунта, поздний каталог и очистку только ссылок без удаления downloads. Изолированный UI: отмена подтверждения не пишет, удаление убирает список, album-save меняет aria-pressed и сохраняет страницу, artist-follow меняет видимую подпись и состояние. Проверка запоздалого открытия подтверждения после ухода со страницы добавлена отдельно. Старые проверки диалогов/вкладок/анимаций/узких окон сохраняются. Отчёты: work/probe118-integrated.json, probe118-write.json, probe118-artist.json, discovery-ui-report.json, artist-ui-report.json.

Полный список подписок не реализован и не заявляется; это требует отдельного подтверждения полного чтения. Натурный проход через все кнопки рабочего окна, screen reader и CPU/GPU-профилирование не выполнялись: реальный сетевой контракт и изолированный UI проверены раздельно.

## 1.1.4 · Главная и имя альбома

Владелец явно разрешил чтение главной/одного альбома, затем отдельно разрешил временное обычное закрытие Wave для диагностических запросов через его адаптер с возвратом приложения. Native Computer Use снова вернул `coordinate input geometry is unavailable`; повторный keyboard input не изменил фокус, дальнейший ввод не выполнялся. Диагностика использовала штатный VkHttpClient и существующий session partition после обычного выхода Wave, без одновременного доступа двух процессов к профилю, без debugger, копирования/decryption cookie-файлов или печати авторизационных значений. Каждая законченная проверка возвращала установленный Wave. Не выполнялись команды добавления/удаления в коллекции, запуска музыки или управления загрузками. Временное закрытие и возврат Wave выполнялись с отдельного согласия владельца.

На реальном VK подтверждены две причины: текущие подписи/типы не совпадали с тремя прежними regex-группами; все8 generated-списков имеют отрицательные ID и отбрасывались общим keyOf. Проверено отдельно: getPlaylistById возвращает ту же generated identity, audio.get читает записи с этим playlist_id. Жанры/настроения персональной главной имеют action.type=play_vk_mix; это не готовые плейлисты.

Повторная проверка исправленного адаптера:12 разделов, state=ready, partial=false. Восстановлены8 алгоритмических списков; один прочитан целиком,100/100 записей с available=true, editable=false. Выбор редакции, новые альбомы, жанровые плейлисты и трековые рекомендации получены из реального ответа. В примере madam до исправления частичный title=unnamed, полный title=damage при той же identity; после исправления albumForTrack вернул damage с confirmed=true. Эти проверки не запускали воспроизведение. Отчёты work/catalog114-audit.json, catalog114-details.json и qa114-real-source.json остаются локально.
