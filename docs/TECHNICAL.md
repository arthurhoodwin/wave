# Техническое устройство Wave

Состояние: **1.1.4 Stable**, 26 октября 2026. Публичный тег [v1.1.4](https://github.com/arthurhoodwin/wave/releases/tag/v1.1.4), канал stable, Windows FileVersion 1.1.4.300. Версии зависимостей закреплены в package-lock.json; приложение — Electron 45, сборочные команды — Node.js 24/Windows x64.

## Границы процессов

```text
Renderer: DOM/CSS, HTMLAudio и Hls.js
    │ разрешённые IPC-команды
Preload: изолированный мост
    ▼
Main: сеанс VK, HTTP-адаптер, хранилища, загрузки и Windows
    ├─ NativePlayer → команды локальному плееру
    ├─ HybridProxy → временные loopback-адреса аудио
    └─ отдельная sandbox-проверка сохранённого файла Chromium
```

Renderer не получает cookies, токены или постоянные подписанные аудиоссылки. Запросы VK выполняет main через отдельную Electron-сессию. Обычное воспроизведение не управляет музыкальной страницей браузера; `engines.cjs`/`catalog.cjs`/`collection-editor.cjs` сохраняют исследовательский путь, не обязательный для пользователя.

Пути в таблице без префикса renderer указаны относительно src/main. Внутри downloads, updates и lyrics находятся собственные модули подсистем; main.cjs остаётся точкой их сборки. Между подсистемами используются явные импорты; общий barrel/index с переэкспортом всех модулей не нужен. Точную спецификацию визуала см. в [DESIGN-SYSTEM.md](DESIGN-SYSTEM.md).

## Хранилища и данные

Профиль: `%APPDATA%/wave-vk-research-client`; VK partition — `persist:wave-vk`. Для тестового форка этот путь и идентичность приложения нужно менять до запуска.

| Каталог профиля | Что хранится |
| --- | --- |
| metadata-v1 | Зашифрованный кэш музыкальных метаданных; это не аудиокэш |
| desktop-v1 | Настройки, позиция/контекст воспроизведения, история поиска, локальные папки |
| personal-v1 | Зашифрованный индекс по аккаунту: история, закрепления, скачанные записи; отдельный `<hash>.queue.dat` для полной очереди |
| updates-v1 | Подготовленные пакеты/планы, резервные файлы, защищённая история обновлений и результат установки |

Аудио находится в выбранной пользователем папке, по умолчанию Music/Wave, с разделением по аккаунту. Рядом могут лежать JSON и обложка. **Аудио и эти соседние файлы не шифруются.** Ссылки потоков/токены не сохраняются в музыкальный JSON.

Выход очищает сеанс и связанные оперативные данные; личная библиотека разделена по аккаунтам и не является одноразовым сетевым кэшем. Не удалять её ради входа или переустановки. Подробности защит/точные границы очистки проверять по provider/main и тестам, не считать весь профиль одним форматом.

## Скачивание и полный список

- API принимает до 5000 выбранных записей с учётом ёмкости локального каталога. Большое выделение не обрезается до 100.
- До 100 queued/running допускаются в рабочую очередь; **сам worker последовательно скачивает по одной песне**. Остальные имеют waiting, а не теряются.
- downloads/download-queue.cjs пишет отдельный зашифрованный журнал всего незавершённого списка атомарной заменой файла. До успешного сохранения новые задачи не запускаются.
- Старое поле queue мигрирует при отсутствии нового журнала. Нечитаемый/неизвестный журнал не заменяется пустым. После перезапуска записи на паузе; доступны общие resume/pause/cancel.
- Старый personal-index остаётся schema 1. Старые версии не понимают новый журнал, но не перезаписывают его; частичные файлы после работы старого клиента могут потребовать повторной загрузки.
- Прямой файл продолжается только при подтверждённых source/strong ETag/Range. Смена ETag, ответ 416 и истёкшая ссылка обрабатываются явно. Неоднозначные сетевые записи VK не повторяются.
- HLS собирается из конечных совместимых сегментов; после паузы начинается заново. Проверяются формат, длительность и SHA-256 до офлайн-доступности.

Лимиты и поддерживаемые варианты — [DOWNLOADS-PLAN.md](DOWNLOADS-PLAN.md). Само название файла сохранено для прежних ссылок; его актуальная часть описывает реализацию Stable.

## Обновления: обязательные инварианты

1. Пакет проверяется встроенным открытым ключом Ed25519, размером/хешем и публичной версией. UI не может отключить проверку.
2. В Electron `app.asar` для обычного fs — виртуальный каталог. Для размеров, хешей и копирования использовать **updates/disk-fs.cjs → original-fs**, не обходить несовпадение основы.
3. Файловый патч относится к точной основе. Проверяются перечисленные файлы, новые/изменённые результаты, пути и обратный план.
4. Подготовка выполняется вне каталога программы. Windows-помощник заменяет файлы после выхода приложения; открытый Electron может удерживать архив.
5. Полного атомарного отката при отключении питания посреди замены нет; предусмотрен полный EXE. Обычная ошибка записи пытается восстановить заменённые файлы.
6. Ключ/контекст safeStorage связан с рабочим профилем. Отдельный helper-профиль может не прочитать его историю; проверки не отключать и ключи профиля не извлекать. Для локальной установки допустим проверенный полный EXE.

## Дополнение 1.1.1: музыкальные ссылки и индикатор

music-links.cjs проверяет host/path/идентичность и создаёт непрозрачный route; renderer не получает key доступа. Ссылки на трек разрешаются через audio.getById и регистрируются обычным absorbRows без запуска плеера. Смена аккаунта/контекста делает запоздалый результат неактивным. Копирование пишет в clipboard только сгенерированный канонический VK URL известной песни/списка; ключи и stream URL исключены. История поиска отбрасывает новые и прежние URL-похожие записи.

renderer/track-wave.js управляет только индикатором строки: IntersectionObserver/visibilitychange и CSS transform; анимация не является спектральным анализом. Обычная EQ-иконка остаётся статичной. Подключение, пауза и playing различимы; prefers-reduced-motion отключает цикл.

## 1.1.2 · Медиатека и описание

library-panel.js управляет только геометрией, library-menus.js — anchored popover с клавиатурой, library-view.js — density; library-folders.js сохраняет локальную структуру через прежний folders API. libraryWidth200–420/libraryCollapsed добавлены в нормализованные desktop preferences и строгий configure allowlist. Drag пишет настройку по завершении, не на каждом pointermove; новые циклические эффекты не добавлены.

Тип альбома из VK type1/is_album проходит через playlistRow/publicPlaylist/метаданные бокового списка и route. Неизвестный type не угадывается по названию или count. playlistDetails разрешает чтение описания только своего редактируемого списка и отклоняет смену аккаунта. rename допускает bounded description; audio.editPlaylist сохраняет состав/no_discover и проверяет title/description/порядок серверным readback. Исследовательский браузерный путь описания не заявляется поддержанным.

## 1.1.2.2 · Валидация длительности загрузки

Физическая длина и SHA256 проверяются как прежде. downloads/audio-duration.cjs потоково считает сэмплы ADTS/MPEG LayerIII, используя небольшую остаточную часть между chunks; для неподдерживаемого MPEG layer/free bitrate возвращается decoder fallback. Успешный Chromium canplay остаётся обязательным. Для измеренного потока canplay.duration может быть предварительной оценкой/Infinity и не заменяет sample duration. Свежий media.duration относится только к запрошенному key; HLS EXTINF — дополнительная сверка, не замена целостности сегментов. Не расширять допуск ради прохождения любого файла.

После exhausted retryable download-http5xx/download-network один повтор source resolve; permanent access/rate не зацикливаются. На сетевых/API write-операциях это не применяется.

## Исполнители

VkHttpClient.artist → artist-catalog.readArtist → network-provider.artist → artist-ui.js. Ссылки/ключи VK остаются в main; renderer получает непрозрачные ID релизов, allowlisted изображения и состояния разделов. Продолжения дочитываются с защитой от циклов; ошибка одного раздела сохраняет уже прочитанное. Неизвестный тип не определяется по count/type=1. Активный artistController отменяется при новом артисте/поиске, уходе, выходе и закрытии; поздний ответ проверяет root и текущую collection до регистрации handles. Локальные сортировки применяются к полученным данным, не обещают серверный порядок полного каталога при ошибке продолжения.

Начиная с1.1.3.1 discography.releases хранит единый порядок полученных собственных релизов. trackSectionTitle различает подтверждённую популярность и generic artist tracks. Fallback аудиопула фильтруется по main/featured identity; случайные записи из соседних блоков не превращаются в популярные.

## Главная и метаданные1.1.4

`home-feed.cjs` читает действительный каталог и отложенный «Обзор». Стандартные группы имеют канонические ключи, остальные поддерживаемые блоки — ключ от server block identity; непрозрачные ID не декодируются. Плейлисты и аудио имеют отдельные парсеры и UI-действия. `play_vk_mix` не становится плейлистом. Generated ID с отрицательным playlist_id поддерживается отдельным playlistKeyOf/parsePlaylistIdentity; audio keys остаются положительными по id.

`PersonalService.recommendations` различает попытки объектом cache-entry: manual retry создаёт fresh-запрос, повтор на уже свежую выполняющуюся попытку её разделяет. Поздняя предыдущая попытка не регистрирует handles. При отказе сохраняются настоящие старые секции с пометкой stale/partial, пустой результат получает короткий TTL. `home-feed-ui.js` обновляет группы/карточки по ID без полной замены DOM.

`album-metadata.cjs` связывает имя только с доказанной album identity, обновляет private/public occurrences, активный трек и историю. Полная playlist-мета не затирается частичной audio.album; параллельные чтения имени объединяются. `album-meta.js` обновляет renderer-копии, а новый loop-reference обеспечивает сохранение desktop-контекста с теми же песнями/порядком. Скрытая проверка placeholder запускается при открытии плеера, не из frame/position loop.
