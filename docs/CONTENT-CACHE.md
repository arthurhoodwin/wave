# Повторное использование контента ·1.1.9.9

27 октября2026. Единый принцип для содержимого: стабильная идентичность и небольшая сигнатура/валидатор вместо сброса готовых данных. Это не обещание, что приватный API VK поддерживает дельту состава: подтверждённого серверного delta-endpoint нет. Состав списков/права/доступность могут по-прежнему требовать чтения текущих rows, после чего содержимое сравнивается локально и переиспользуется без повторной загрузки изображений/текстов.

## Что устранено

- `provider.absorbRows`: свежий sparse ответ ранее записывал cover=undefined поверх готовой обложки; теперь допустимые новые поля заменяют старые, отсутствующие необязательные не стирают их. Идентичность строки — playlist/scope/audio key/occurrence, а не название. Сигнатура SHA256 меняется по контенту; неизменившиеся public row objects сохраняются.
- `image-cache.js`: disconnected img ранее терял src и observer навсегда. При временном detach/reorder decoded src сохраняется, присоединённый узел вновь наблюдается. Готовые строки patch-ятся на месте, в том числе при local/status change; изменение одной обложки держит прежние пиксели до готовности новых.
- При изменении названия/исполнителя меняется signature; при доступности/owned/длительности применяются свежие значения. Кэш обложки не даёт права воспроизводить заблокированную запись. Одинаковые названия разных аудио-ID не объединяются.

## Метаданные

`content-cache.cjs`: до20000 записей на активный account root, content key=VK audio identity, fingerprint title/artist/time + cover/artists/album fields. Сохраняются реальные названия вместо временных placeholder; подтверждённый альбом не заменяется unnamed, но новая содержательная albumTitle инвалидирует прежнюю привязку. `metadata-store` остаётся единственным persistent зашифрованным снимком текстовых метаданных: tracks/playlists/descriptions и найденные lyrics; схема обратно совместима, старые снимки читаются. При restore контентный индекс заново строится из проверенных записей.

Изменение одного списка не удаляет metadata других. Пустое описание с явной строкой означает удаление описания; отсутствие поля означает неполный ответ и сохраняет готовое. Описания/обложки/альбомы не проверяются дополнительным запросом на каждую строку. Авторизованные audio URLs, cookies и access tokens не кладутся в новый content cache.

## Изображения

`artwork-content-cache.cjs` общий для обложек песен/списков, шапок, баннеров/аватаров и мини-плеера; палитра использует те же bytes и revision, не отдельный сетевой fetch. IPC принимает только проверенный HTTPS CDN-URL из allowlist, без cookies/редиректа; mini имеет доступ только к readonly artworkImage, не ко всем music-командам. Не-VK origin отвергается.

- key=SHA256(account root + URL); URL не хранится в plaintext индексах, файл/метаданные — в отдельной account-hash папке content-art-v1.
- JPG/PNG/WebP, не более2МиБ, реальное декодирование nativeImage перед сохранением, ограничение изображения20млн пикселей. Прямой CDN fallback сохраняется для старых/неподдержанных изображений и недоступного кэша.
- Проверка размера/SHA256 на чтении; свежие24ч bytes берутся с диска без сети. Позже If-None-Match/If-Modified-Since,304 обновляет проверку без передачи картинки;200 сохраняет новую revision. Ошибка сети при наличии годной старой копии отдаёт её.
- По2 сетевых задачи одновременно, до256 pending, объединение одинаковых запросов. Renderer — LRU96 payload/16МиБ, ленивые видимые изображения, прежний offscreen-limit96. Дисковый image budget128МиБ/3000 файлов на аккаунт, LRU удаляет только собственные hashed files; metadata/временная запись дают небольшой служебный overhead.
- Обычное обновление экрана/лайк не очищает кэш. Явная кнопка обновления revalidate-ит видимые обложки условными HTTP-запросами, сохраняя старые пиксели до готовности новых.
- Выход отменяет задачи, очищает память и удаляет только image-папку текущего аккаунта. Смена аккаунта не возвращает ему чужие bytes; очистка не трогает cookies/подпись/установку/скачанную музыку.

Не вводится per-row таймер или постоянный redraw. SVG-обложка лайков — статический локальный asset и не сетевой контент. Необработанные большие исходники не являются обещанным offline photo archive.

## Тексты

Положительные результаты остаются до7дней, пустой поиск —2минуты. Ключ: VK key + title + artist + duration, не временный renderer id; смена обложки не вызывает новый поиск текста. Переход к другой записи/изменение её значимых полей меняет ключ. До64 записей/4МиБ, текст/syncedLyrics/timings/source/credits проходят отдельный whitelist `lyrics-cache-data.cjs`. Persistent данные входят в шифрованный MetadataStore; после restart годный текст доступен без повторного VK/Genius/LRCLIB запроса, в том числе офлайн. Явный retry сбрасывает source и VK lyrics-cache для записи; старый cached success не подменяет требуемое повторное чтение.

## Проверки

Node: sparse merge, source identity, row reuse, placeholder/real-album update, restart, conditional304/new revision, disk hit/dedup, URL/account isolation, lyrics persistence/whitelist, права не из кэша. Electron: native PNG сохранён/повторно прочитан новым экземпляром без сети; вставка одного track даёт requests=1 для нового изображения, старые row/img references равны; detach/reinsert не оставляет blank. Проверки артистов/mini/metadata/OTA сохраняются. Реальная пользовательская коллекция не менялась, натурные20тыс треков/CPU/GPU не профилировались. Итоги выпуска — [VALIDATION.md](VALIDATION.md).

IPC-регрессия закрыта в1.1.9.9: main принимает optional refresh для lyrics/artworkImage. Тест content-ipc.test.cjs соединяет реальный preload с реальной регистрацией команд и провайдером текста, включая cache hit и forced retry.

## Beta2 · качество без больших текстур в каждой строке

artwork-sources.cjs выбирает наиболее крупный валидный photo_N/size до1600px; если известны только большие размеры — самый маленький из них. Размеры и aspect metadata сохраняются, URL не переписываются. Это распространяется на песни/плейлисты/альбомы/поиск/профили; фото произвольного артиста не объявляется квадратным только из-за photo_N.

На диске остаётся один оригинал с прежними ETag/лимитами. getSized проверяет width64…1600 и создаёт thumbnail по nativeImage без увеличения малого исходника; JPEG сохраняется JPEG90, PNG/WebP с возможной прозрачностью — PNG. Отдельный account+revision+width LRU64/8МиБ очищается вместе с account cache. Renderer выбирает128/256/512/1024/1600 по фактической ширине иDPR, повышает размер при увеличении окна; ключи его LRU включают размер. Главный плеер получает компактный128/256px вариант поDPR, развёрнутый — крупный. Renderer сохраняет прежние96/16МиБ и ленивую загрузку.

Read-only mini artwork IPC также принимает bounded width; lyrics не принимает этот параметр. Реальный800px тестовый PNG уменьшен до128, вариант переиспользован тем же объектом; повторной сети нет. Новые URL более крупной картинки обновляют content fingerprint, старый metadata cache целиком не очищается. Старые offline-копии на диске автоматически не переписываются.
