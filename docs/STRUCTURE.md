scripts/                Ресурсы, пакетирование, публикация, уборка, Electron-gate
tests/                  Node.js-проверки по подсистемам

docs/images/            Обезличенные демонстрационные снимки
releases/LATEST.md       Единственные заметки к текущему выпуску

Рабочий checkout проекта — outputs/wave-github в данной рабочей области. Прежний outputs/vk-desktop не является вторым источником изменений. В Git не включаются dist, node_modules, собственные тестовые профили, аудио, cookies, секреты или приватный ключ подписи.

## Как поддерживать документы

- README и releases/LATEST.md — **для пользователя**: изменения и действия, без статистики тестов, внутренних протоколов и отчёта о разработке.
- DESIGN-SYSTEM/TECHNICAL/UPDATES — текущие правила. Не накапливать противоречащие инструкции под заголовками Alpha/Beta; историю оставлять в CHANGELOG/аудитах.
- VALIDATION различает код/автотесты, искусственный runtime, реальный ПК и неподтверждённые сценарии. Отложенное не отмечать пройденным.
- ROADMAP не повторяет реализованные функции как будущую разработку. Важные пожелания владельца и исключённые функции сохраняются.
- При релизе заменять **только releases/LATEST.md**; отдельные RELEASE-VERSION.md не заводить. Текст дублируется в GitHub Release.
- При изменении цветов/компоновки обновлять DESIGN-SYSTEM и демонстрационные изображения. Цвета сначала сверять с theme.css.

## Релизы и артефакты

Обновить package/lock, releaseVersion/releaseChannel, Windows buildVersion, имя EXE и UI-версию. Выполнить Node/Electron-проверки, сборку и пакетирование по [UPDATES.md](UPDATES.md). Опубликовать черновик только после проверки CI и digest каждого файла.

Исторически в Stable 1.1.0 четыре вложения: EXE, канонический полный `.waveupdate`, отдельный маленький пакет от RC 1, SHA256SUMS.txt. В Alpha/Beta/RC ставить prerelease и не менять Latest. Обычную Stable явно назначать Latest. Уже опубликованные теги/бинарники не переписывать ради сортировки; изменения требуют следующей версии.

Исторические 1.0.61/1.0.62 — исправления 1.0.6. Их страницы опубликованы как v1.0.6.1/v1.0.6.2; исходные Git-теги сохранены. Старые Alpha 2/3/6 доведены до публикации, чтобы черновики не отображались владельцу выше новых выпусков. Старые прямые ссылки с прежними именами нужно обновлять; даты/коммиты ради порядка не подменять.

`npm run artifacts:clean` удаляет только устаревшие именованные артефакты непосредственно в dist. Текущий дополнительный малый пакет extraUpdateBase сохраняется. Текущий win-unpacked нужен как точная основа следующего патча; не заменять его рабочей установкой с неизвестными изменениями.

## Границы модулей и локальная карта

`src/main/main.cjs` собирает подсистемы и регистрирует IPC. `provider.cjs` остаётся фасадом музыкальных команд; интерфейс, preload и данные профиля сохраняют свои границы. Каталоги downloads/updates/lyrics выделены по связям исходников, тестов и документации, найденным в Graphify и проверенным по коду.

- В downloads/ находятся менеджер, полный журнал очереди, HTTP/HLS, проверка скачанного файла и автономные обложки. Общая личная библиотека и прокси воспроизведения остаются отдельными сервисами уровнем выше.
- В updates/ находятся форматы пакетов, проверка подписи/основы, GitHub-доставка, запуск помощника и контроль старта. Windows-помощник остаётся в build/windows; его путь в упаковке и формат сохранённого плана не меняются.
- В lyrics/ находятся резервные источники и разбор VK-текста. Сетевой сеанс VK остаётся в vk-http.cjs, отображение и привязка к аудиочасам — в renderer.
- Тесты сохраняют предметные имена в tests/, общие фикстуры — tests/helpers/, настоящий Electron-прогон — tests/electron/. Сборочные скрипты импортируют рабочие модули по новым путям.

Локальная `graphify-out/` содержит graph.html, graph.json и GRAPH_REPORT.md. Она игнорируется Git и не входит в приложение: граф, кэш и путь Python зависят от рабочего окружения. После изменения исходников обновляйте граф из корня репозитория: `$graphify . --update`. Для чистой сборки используйте `$graphify .`.

Граф помогает найти кандидатов для изменений; отсутствие связи не доказывает отсутствие зависимости. Особенно проверяйте динамические вызовы, IPC, CSS, минифицированный сторонний код и пути упаковки. Перемещение модуля требует обновить его входящие и исходящие относительные импорты, тесты и текущую документацию. Поведение и форматы данных не меняйте заодно с переносом без отдельной причины.

В 1.1.1: EXE, канонический файловый пакет от точной Stable 1.1.0 и SHA256SUMS.txt. src/main/music-links.cjs — проверка и разрешение обычных музыкальных ссылок; renderer/music-links.js и track-wave.js — интерфейс ссылок и индикатор строки.
