# Структура репозитория

```text
assets/icons/          Логотип и иконки Wave
build/windows/         NSIS и помощник установки
build/update-public.pem Открытый ключ проверки обновлений
docs/                  Роадмап, архитектура, дизайн и инструкции
docs/images/           Иллюстрации README
releases/LATEST.md      Заметки только к актуальному релизу
scripts/               Подготовка ресурсов, упаковка и публикация
src/main/              Electron, VK, кэш, плеер и Windows
src/preload/           Ограниченные мосты IPC
src/renderer/          Интерфейс, шрифты и Hls.js
tests/                 Автоматические проверки
dist/                  Результат сборки; не хранится в Git
.github/               CI и шаблоны обращений
```

В корне остаются README, лицензия, правила участия, политика безопасности, package-файлы и команды запуска. Все рабочие исходники находятся в этом checkout. Предыдущий каталог `outputs/vk-desktop` — прежняя рабочая копия, а не второй источник дальнейших изменений.

## Правило релизных заметок

В дереве репозитория хранится только **releases/LATEST.md**. При следующем релизе заменяем его содержимое и номер версии. Старые отдельные RELEASE-файлы не возвращаем; старые публикации остаются в GitHub Releases и истории Git. Краткий общий CHANGELOG расположен в docs.

1. Обновить package.json/package-lock.json, подпись версии интерфейса и releases/LATEST.md.
2. Выполнить `npm test`, `npm run dist`, подготовить `.waveupdate` и `dist/SHA256SUMS.txt` по [инструкции](UPDATES.md).
3. Проверить `npm run release:check`, создать и отправить соответствующий тег `vVERSION`.
4. `npm run release -- --draft` создаёт черновик GitHub Release с **точным содержимым LATEST.md**, установщиком, пакетом и хешами. Проверить черновик и опубликовать. `npm run release` публикует сразу.

Публикация выполняется только явно запущенной командой. CI тестирует код; ручной workflow собирает установщик, но не имеет закрытого ключа официальных обновлений.
