## Конкретные пробелы, влияющие на порядок работ

1. **Отмена в backend не означает доступность переключения в UI.** `src/main/native-player.cjs` отменяет старые команды поколениями, но `src/renderer/app.js` оставляет клик по строкам доступным, однако next/previous блокируются через `state.busy`, а транспортные пути имеют собственные guards. Критерий мгновенной отмены нужно проверять по всем путям выбора, а не объявлять выполненным по одному тесту NativePlayer.
2. **Текст из кэша не всегда показывается офлайн.** `src/main/vk-http.cjs:lyrics` имеет ограниченный кэш, но `provider.cjs:lyrics` сначала требует online; сетевой метод начинает с connect. Повторное открытие без сети пока нельзя обещать.
3. **Лайк хранится в нескольких местах.** Backend обновляет записи по native key, renderer после операции — по UI trackId. Тот же трек из поиска и медиатеки может иметь разные UI ID. Нужна единая модель состояния, без сведения разных версий песен по одному названию.
4. **История навигации ≠ история прослушивания.** `navigation.snapshots` сохраняет открытые виды; `state.history` — временное состояние плеера. Это не готовый источник постоянного раздела «Недавно прослушанное».
5. **Внутренние счётчики ≠ диагностика для пользователя.** `VkHttpClient.stats` есть, но безопасного экспортируемого отчёта нет.
