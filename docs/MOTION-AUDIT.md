# Анимации Wave · аудит 1.1.7

26 октября 2026. Исходная точка —1.1.6.1. Проверены собственные renderer-файлы; vendor/HLS не относится к дизайну. Использован better-ui, карта graphify сверена с текущими исходниками. Этот документ фиксирует причины, решения и границы проверки; наличие CSS не считается доказательством плавности на любом ПК.

## Главные выводы

1. Движение уже было: lifecycle диалогов, волна текущей песни, подсветка строк текста, hover/press. Переписывать их целиком незачем.
2. Старый `window-chrome.js` затемнял весь `main` при смене route; самостоятельного перехода внутренних вкладок артиста не было. Общая заливка не объясняла, какая область изменилась.
3. Меню медиатеки, действий строки и новые listbox открывались/закрывались без перехода. Toast имел только входной keyframe; быстрое закрытие/повтор не было единым состоянием.
4. `setIcon` заменял SVG; play/pause, repeat/repeat-one, download/check/retry не имели стабильных слоёв для обратимого перехода.
5. Сохранённые старые карточки подборок — ошибка согласования DOM, а не эффект анимации. При изменении signature map получала новый узел, прежний оставался дочерним элементом сетки. Исправление удаляет прежний узел и любые осиротевшие дочерние элементы; один ID отображается один раз в секции.

## Владельцы и правила

- `src/renderer/motion.js:3`: один владелец Web Animations на узле; отмена предыдущего job, fallback при остановленных кадрах, конечный callback только актуального job. Новый `fade` использует тот же механизм.
- `src/renderer/motion-details.js:4`: семантические ключи страницы/песни/вкладки. Повторный controls(), position tick, та же route или метаданные песни с тем же ID не запускают эффект заново. Остановка JS-эффектов при document.hidden и смене reduced-motion.
- `src/renderer/motion-details.css:1`: устойчивые слои SVG; CSS transitions для интерактивного состояния и нативных popover/display/overlay. Нет таймера на строку, общего MutationObserver на каждый progress tick и transition:all.
- Диалоги остаются у `dialog-manager.js` + `motion.js`; старая отдельная анимация main удалена из window-chrome, где остаётся только подпись окна.

## Производительность, доступность и приёмка

- Данные/aria/focus меняются в текущем действии; анимация не участвует в network promise. Никаких await перед запуском музыки, лайком или seek ради дизайна.
- Скрытие окна и смена reduced-motion отменяют активные новые JS-fade; циклическая волна имеет прежнюю отдельную остановку видимости. Новых бесконечных анимаций нет.
- Reduced-motion: JS-opacity≤100мс, меню/иконки opacity80мс, без translate/scale/blur; глобальные привычные отключения остаются. На готовом статическом кадре состояние понятно без движения.
- Native popover display/overlay transitions разрешены Chromium текущего Electron; закрытый слой сразу перестаёт ловить pointer, даже если ещё угасает. Escape и выбор пункта не ждут exit.
- У слоёв иконки максимум2–3 SVG, aria-hidden; живые объявления не дублируются. Геометрия duration/like/download/# не меняется.
- Тестировать реальные последствия:20 быстрых смен значка дают правильную последнюю active-layer;100 controls() с теми же данными не запускают fade; повторные metadata-обновления карточек не увеличивают их число и не теряют фокус.
- На изолированном стенде проверить вкладки/меню/Escape, reduced-motion, forced-colors, узкие ширины и zoom200%. Не занимать рабочее окно VK ради визуальной проверки без действующего разрешения.

**Не проверено:** трасса CPU/GPU на пользовательском ПК, субъективное качество каждого перехода на10% playback, полноценный screen-reader walkthrough, native show/hide/fullscreen всех сочетаний окон. Ограничение не скрывается: исчерпывающая карта исходников и состояние тестов не означают аппаратную сертификацию плавности.
