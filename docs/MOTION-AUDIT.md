# Анимации и детали интерфейса Wave

25 октября 2026. Аудит исходников Wave 1.1.0 после структурной уборки; пожелание владельца — оживить небольшую волну вместо номера играющей песни и системно проработать движение новых частей интерфейса. Это **план**, а не описание уже внесённого поведения. Связанные документы: [дизайн-код](DESIGN-SYSTEM.md), [роадмап](ROADMAP.md).

Применён навык better-ui: сохраняем графит, умеренный мятный акцент и текущую плотность. Движение объясняет состояние; исправный ввод, фокус, скорость действия и тайминг звука важнее декоративного эффекта.

## Что уже работает

- `renderer/motion.js:3–16`: один владелец анимации поверхности, отмена старого завершения, enter 300 ms / +12 px, exit 150 ms / −12 px, easing cubic-bezier(.2,0,0,1); reduced-motion — opacity 100 ms. Fallback timeout учитывает приостановку кадров в перекрытом окне.
- `renderer/dialog-manager.js:2`: close/reopen во время выхода, сохранение opener и возврат фокуса; не заменять это второй независимой CSS-анимацией.
- `renderer/design.css:13`, `polish.css:22`: нажатие ряда кнопок scale .96 / 150 ms; фоны 100–120 ms. Hover/press уже есть, а не полностью отсутствуют.
- `renderer/song-view.js:8–10`, `song-view.css:19`: текущая строка выбирается по аудиочасам; smooth autoscroll, сдвиг/фон 90–100 ms, остановка сопровождения при ручной прокрутке. Позднее правило `song-view.css:34` делает фон прозрачным и оставляет светлый текст с мятной линией; сдвиг 4 px в no-preference остаётся. Проверять итоговый каскад, не один ранний файл.
- `renderer/virtual-list.js`: переиспользование DOM, сохранение фокуса/якоря и измерение высот. Это ограничение для motion, а не место для запуска каскада при каждом mount.

## Волна текущего трека

Первый этап — 1.1.1, рядом с уже запланированными музыкальными ссылками:

- Четыре независимые полоски внутри прежнего места номера; фиксированные размеры колонки/кнопки, currentColor, без смещения названия.
- Во время подтверждённого проигрывания — разные фазы scaleY, циклы 800/1000/900/1100 ms; центр/transform-box и высоты проверить в реальном Chromium. Без мерцания opacity и без случайного JS-таймера на каждую полоску.
- Это условный **индикатор воспроизведения**, а не спектрограмма. Не создавать новый аудиоанализатор ради этой детали и не обещать синхронизацию полос с басом.
- На паузе — замершая нейтральная волна у текущего трека; текущая строка остаётся отмеченной. В состоянии подключения/буферизации не изображать уже играющий звук; сохранить отдельный текст/статус. После ухода трека — номер строки.
- Не анимировать значок equalizer глобально: он также используется для обозначения настройки EQ. Scope — текущая видимая строка списка.
- При reduced-motion — неподвижный знак. В скрытом окне/вне видимой области анимация приостановлена, снятая виртуальная строка не оставляет работающих обработчиков.
- Кнопка номера продолжает запускать трек, label соответствует состоянию; декоративные полоски aria-hidden, постоянных live-объявлений нет.

## Общие сценарии и конкретные значения

| Сценарий | Договорённость для разработки |
| --- | --- |
| Dialog enter/exit | Сохранить 300/150 ms и cubic-bezier(.2,0,0,1); только один motion owner |
| Нажатие доступной кнопки | Существующие .96 / 150 ms ease-out; не повторять поверх press ещё один scale |
| Контекстная смена значка | Слои в прежней геометрии; opacity/scale 300 ms cubic-bezier(.2,0,0,1), scale .25→1 для редких смен, без bounce. При серии команд отменять/перенаправлять эффект; действие и label сразу |
| Частые изменения статуса строки | Без scale/blur, opacity/background не дольше 150 ms. Не накладывать 300 ms icon-swap на каждый progress tick |
| Смена обложки/подписи | Opacity 150 ms, один раз по новому track ID; обновление позиции/громкости ничего не перезапускает |
| Появление подборки/ошибки/empty | Opacity 150 ms; содержимое доступно сразу, без очереди каскадов на каждую карточку |
| Прогресс загрузки | Состояние/значение сразу; допустим визуальный переход заполнения до 100 ms, только вперёд для той же задачи. Пауза/ошибка не продолжают изображать прогресс |
| Скролл к строке текста | Выделение точно по аудиочасам; прокрутка отдельно, отменяется ручным вводом и новым seek. Не вводить задержку в метки ради анимации |
| Частые действия | Поиск, ввод, сортировка, hover строки, перемотка, drag громкости — без перестановочных/каскадных эффектов; фокус и pointer hit area стабильны |
| Reduced motion | Перемещения/scale/постоянные циклы отключены; короткая opacity до 100 ms либо мгновенный переход для частых событий. Уважать изменение предпочтения во время сеанса |

Называть точные CSS properties, без transition:all. Не анимировать размеры тысяч строк и постоянный blur. will-change — только при измеренном торможении, на нужное свойство и время. Если раскрытие небольшой группы требует измерения высоты, оно ограничено одной группой; очередной virtual-list measurement не должен зацикливать анимацию.

## Мелкие детали дизайна

- Проверять оптический центр play/pause и волны, ширину duration/like/download, одинаковый отступ до троеточия; не сдвигать их при изменении статуса.
- Сердечко остаётся мятным при добавлении, скачанная копия — нейтральная галочка. Цвета берутся из theme.css; ради новых эффектов зелёные поверхности не возвращаются.
- Одинаковые действия имеют одинаковые loading/disabled/focus/pressed состояния в списке, нижнем баре, полноэкранном и мини-плеере.
- Обложки получают стабильный placeholder; загрузка картинки не меняет размеры карточки. Прозрачный логотип не получает рамку обложки.
- В 1.1.3 переработать карточку/шапку артиста: широкий баннер и аватар — разные роли. Проверить реальные профили с разными исходными изображениями, светлым/пёстрым фоном, длинным именем и ошибкой загрузки. Резервировать геометрию шапки; появление изображения — opacity до 150 ms, без растяжения и перезапуска при обновлении метаданных. Название и кнопки читаются до и после загрузки; reduced-motion — до 100 ms.
- Ошибка, empty и skeleton различимы. Skeleton не проигрывает бесконечный яркий shimmer; на тёплом переходе из кэша его не показывать ради эффекта.
- Высота мини-плеера остаётся по содержимому, таймер/громкость/длинное название не прыгают; панели и dropdown не перекрывают транспорт.
- Статическая подсказка, иконка или подпись дублируют смысл движения; no-motion и forced-colors остаются понятными.

## Как проверять перед выпуском

Пока выполнено **только чтение исходников и каскада стилей**, без проверки реального окна/инструмента Animations. Не проверены частота кадров, 10% playback анимаций, скрытие окна, смена системного reduced-motion, фактическая оптическая центровка и потребление CPU/GPU. Числа ниже — критерии будущего приёма, а не результаты замеров.

- Играть → пауза → продолжение → подключение → ошибка → другой трек, в том числе офлайн. 20 быстрых команд оставляют правильное последнее состояние, без позднего callback старой анимации.
- Tab/Space/Escape, mouse back, drag и seek работают во время перехода, а не после него; фокус не исчезает вместе с SVG/строкой.
- 10 000 треков, прокрутка с виртуализацией и фоновое обновление: число анимируемых узлов ограничено видимой областью; одинаковые данные не перезапускают enter.
- Скрытие/возврат окна и мини-плеера, 200% zoom, длинные русские названия, no-preference/reduce и forced-colors.
- Performance trace на записанной Windows-конфигурации: нет новой долгой работы >50 ms от простого feedback; 60 Hz ориентир — кадр 16,7 ms. Не объявлять smooth по одной записи CSS.
- Отдельная визуальная проверка на 10% скорости: прерывание, обратный ход, совпадение статического конечного состояния и hit area. Показать известные непроверенные сочетания.

Нужны проверки состояния/отмены и регрессий, а не тесты, утверждающие только буквальное наличие keyframes. Новые снимки проверяют геометрию; они не доказывают качество движения.
