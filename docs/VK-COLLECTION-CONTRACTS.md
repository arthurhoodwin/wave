# VK: коллекция и подписки ·1.1.8

27 октября2026. Доступность проверена в действующем сеансе с явным разрешением владельца: только новый временный плейлист, временно сохранённый ранее несохранённый альбом и обратимая подписка одного артиста. Старые пользовательские плейлисты не удалялись. После каждого итогового сценария набор идентификаторов сохранённых списков и состояние подписки совпали с исходными.

## Установленные контракты

| Действие | Запрос | Подтверждение и ограничение |
| --- | --- | --- |
| Удалить собственный плейлист | audio.deletePlaylist(owner_id,playlist_id) | Владелец равен текущему аккаунту, свежие permissions.delete/edit=true, объект не album. Полный audio.getPlaylists после записи не содержит ID |
| Сохранить альбом | audio.followPlaylist(owner_id,playlist_id,access_key при наличии,ref) | Ответ owner_id/playlist_id — идентичность сохранённой копии, может отличаться от исходника. Исходный getPlaylistById: is_following=true и followed с тем же ID; копия присутствует в полном getPlaylists и имеет тип album |
| Убрать сохранённый альбом | audio.deletePlaylist по followed, а не по произвольному исходному ID | Подтвердить связь original/followed и членство в своей медиатеке; после записи копии нет в полном списке, исходный is_following=false. Исходник остаётся доступным |
| Подписаться/отписаться | audio.followArtist / audio.unfollowArtist(artist_id,ref=artist_page) | Канонический числовой ID из artists[].id сохраняется строкой, без преобразования в Number; route/domain для запроса недостаточен. Повторный catalog.getAudioArtist подтверждает artists[].is_followed |
| Разрешение подписки | catalog.getAudioArtist | can_follow разрешает новое добавление; is_followed даёт текущее состояние. Уже подписанному доступна отписка. Нет выдуманного локального follow |

API возвращал ошибку100 при route/domain вместо канонического ID и при отсутствии обязательного ref; окончательный сценарий с ID/ref прошёл. Ошибочные запросы не изменили подписку. Legacy al_artist.php/hash в поставку не добавлен: найден и подтверждён штатный API-контракт. Переход HTML-страницы артиста через диагностический fetch не был надёжным; он не используется реализацией.

## Слои реализации

- `src/main/collection-management.cjs`: свежие права, идентичность оригинала/сохранённой копии, одно write-действие и read-back, обновление handle/cache и очистка ссылок.
- `provider.mutate`: прежняя последовательная очередь и журнал операций; новые команды не создают конкурирующую очередь. При неподтверждённом результате состояние uncertain, без автоматического повторения записи.
- `onPlaylistRemoved`: очистка pins/visits и папок через последовательную очередь; downloads, музыка «Мне нравится» и текущий аудиофайл не изменяются. Tombstone не позволяет старому ответу каталога вернуть удалённый объект.
- `network-provider` + `artist-catalog`: непривилегированный opaque handle в renderer, канонический ID и маршруты остаются в main. Новый сеанс читает настоящее состояние заново.
- `collection-management-ui.js`: trash в шапке/меню собственного плейлиста, отдельное подтверждение, состояние альбома и кнопка подписки. Закрытый/отменённый диалог не пишет; ответ после ухода со страницы не открывает старое подтверждение. Анимации используют существующий дизайн-код.

У неопределённого ответа нет обещания, что сервер ничего не изменил: пользователь получает просьбу обновить страницу перед повтором. Нельзя объединять альбомы по названию или удалять исходник чужого владельца на основании одной кнопки renderer.
