# Тестирование Wave

## Текущий срез · 1.1.3.2 Stable

25 октября 2026: **342 Node.js-тестов** и отдельный обязательный Electron ASAR-gate. Музыкальные ссылки и native видимость индикатора покрыты отдельными сценариями; точные результаты публикации/установки и границы — [VALIDATION.md](VALIDATION.md). Эти цифры относятся к срезу 1.1.3.2, в последующих версиях источник истины — фактический прогон.

## Запуск

Нужен Node.js 24, как в Windows CI.

```powershell
npm test
npm run test:updates-electron
node --test --test-timeout=15000 tests/download-manager.test.cjs
node --test --test-name-pattern="signed version must equal" tests/github-updater.test.cjs
```

Набор не обращается к настоящим аккаунтам VK, Genius или GitHub. Сеть подменяется; HTTP-проверки файлов используют локальные серверы. Установщики в тестах — синтетические байты с тестовыми ключами, реальные установщики не запускаются.

По умолчанию у каждого теста есть предел 15 секунд. Массовые сценарии на 150 файлов имеют ожидание до 12 секунд; Windows helper-интеграции — до 20 секунд на subprocess и до 45 секунд на сценарий. Ошибка запуска/таймаут не считается ожидаемым отрицательным результатом. Ожидания событий должны быть привязаны к событию или условию с дедлайном. Для проверки задержки восстановления используются управляемые часы. `tests/helpers/` не запускается как отдельный набор: здесь находятся общая фабрика загрузок, временные каталоги, искусственные WAV/ADTS и ограниченное ожидание.

## Границы автоматических проверок

- `ui-playback` выполняет настоящий `app.js` в модели DOM. Это проверка состояния и взаимодействий, не проверка CSS или полноценного Electron-окна.
- `download-validation` подменяет окно декодирования и проверяет правила принятия длительности. ADTS в транспортных тестах — структурная фикстура, а не доказательство декодирования AAC.
- Подмена кодировщика в тестах хранилища проверяет вызов адаптера и правила хранения, а не Windows DPAPI. Подпись пакетов и часть шифрованных фикстур используют настоящие криптографические операции с отдельными тестовыми ключами.
- Реальные ответы VK, источники текстов, настоящие HLS-варианты и их кодеки проверяются отдельно. Внешний сервис не считается проверенным по одному синтетическому ответу.
- Вёрстка, палитра, Tab/Enter/Space/Escape, 200%, reduced motion и разные Windows-компьютеры требуют отдельного браузерного/ручного прогона. Цветовой снимок строк CSS не заменяет такую проверку.

### Усиленные ожидания

- Подписанная версия сравнивается с опубликованной после успешной проверки метаданных и фактической загрузки; утверждаются точная ошибка несовпадения и очистка файла. В узкой отрицательной проверке отключение этого условия действительно приводило к падению теста; исходник восстановлен.
- Переход на предварительный выпуск проверяет настоящий сохранённый установщик стабильной версии и последующий откат, а не только номер запускаемой версии.
- Публикация проверяется для Alpha, Beta, RC и Stable: предварительные выпуски не назначаются Latest.
- Быстрый лайк проверяется через VkProvider для известного подтверждения и для подтверждения чтением: одна запись, немедленное состояние коллекции, сохранение исходного идентификатора.
- Готовность выбранного плейлиста проверяется выполнением сформированного скрипта над моделью документа с заполненной фоновой медиатекой и ещё пустым целевым списком. Форматирование строки JavaScript больше не является условием прохождения.
- Настройки медиатеки проверяют оставленный компактный вид; поиск и выбор порядка плейлистов не объявляются актуальной функцией.
- Сценарий renderer оформлен именованным тестом вместо отдельного скрипта с ручным `process.exitCode`.

Актуальное число и результат сообщает `npm test`. Числа в заметках опубликованных выпусков описывают набор на момент соответствующей сборки и не переписываются задним числом.

## Дополнение Beta 7: ASAR внутри Electron

`npm run test:updates-electron` — обязательный отдельный CI-шаг после 290 Node.js-тестов. Node готовит два настоящих ASAR и подписывает искусственным ключом файловый пакет. Electron сначала подтверждает виртуализацию обычного fs.stat, затем штатным менеджером готовит патч и завершает процесс. Только после выхода Windows-помощник заменяет архив. Новый Electron проверяет результат и готовит обратный план; после его выхода выполняется откат и сверяются исходные байты. Изменённый архив отклоняется.

Ранее замена обычных файлов из Node не покрывала ASAR-виртуализацию и открытые Electron дескрипторы. Новая проверка не запускает рабочий Wave, не использует профиль/аккаунт владельца и не исполняет NSIS. Для ручного прогона на локальной Windows процессу Electron нужен доступ к своему runtime-каталогу.
