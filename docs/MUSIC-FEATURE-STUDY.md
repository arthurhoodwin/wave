# Spotify, VK Музыка и Wave: исследование для 1.2

25 октября 2026. Сравнивается Wave 1.1.0 Stable с актуальными локально установленными ресурсами Spotify и публично полученными ресурсами VK. Основа Wave — исходники `1e4732e` после структурной уборки. Итоговое решение о версиях — [ROADMAP.md](ROADMAP.md).

## Метод и границы вывода

1. REA статически разобрал выбранные файлы **новой** поставки Spotify; затем выполнена ограниченная ручная проверка обработчиков/настроек с байтовыми смещениями. Это не авторизованный runtime Spotify и не утверждение, что локальная сборка является самой новой в мире.
2. REA открыл публичный `https://vk.com/audio` в собственном headless Edge с пустым профилем, дождался 3 секунд и записал DOM/URL. Получена `https://vk.ru/audio`, показаны музыкальные строки/плейлисты; браузер завершён. На кнопки воспроизведения, подписки, лайка и авторизации не нажимали. Используемый владельцем Wave/браузер не занимали.
3. По объявленным публичной страницей script URL скачаны ресурсы. REA разобрал пять выбранных музыкальных JS. Последующая ручная проверка буквальных методов/обработчиков отмечена отдельно: она не выдаётся за автоматически восстановленный полный путь вызовов.
4. Публичные описания функций перепроверены по официальным Spotify/VK. Заявление компании доказывает существование продуктовой функции, но не доступность её API в Wave.
5. Наша реализация сверена сначала с Graphify, затем с исходниками, разрешёнными командами, хранилищами и UI. Отсутствие в ограниченном обзоре не означает отсутствие во всех старых прототипах или клиентских платформах.

Уровни ниже: **static** — поставляемый обработчик/настройка; **public runtime** — только наблюдавшаяся анонимная страница; **official** — описание производителя; **Wave source** — существующий исходный контракт. «Требует проверки» означает непроверенный серверный путь, а не готовую функцию.

Официальные подтверждения: [радио на основе сущности](https://support.spotify.com/us/article/spotify-radio/), [локальные файлы](https://support.spotify.com/us/article/local-files/), [shuffle с учётом недавнего прослушивания](https://newsroom.spotify.com/2025-11-13/shuffle-update-fewer-repeats/). Описание Spotify подтверждает функцию, но её закрытый алгоритм не становится частью Wave.

Spotify также описывает [папки и массовое редактирование](https://newsroom.spotify.com/2026-05-28/playlist-folders-mobile-queue-controls-updates/). Эти базовые сценарии уже есть у нас; мобильные обновления Spotify не являются недостающей функцией Windows Wave. [Исключение из профиля вкуса](https://support.spotify.com/us/article/exclude-playlists-or-tracks-from-your-taste-profile/) отличается от скрытия песни. В исследованных шести JS полный taste-profile механизм не установлен; по аналогии нельзя обещать изменение вкусов VK.

## VK: что полезно для оболочки

| Возможность | Конкретная находка в публичном ресурсе | Степень подтверждения |
| --- | --- | --- |
| Непрерывный Микс | `c7995f35.54855bb3.js`, byte 26213: getStreamMixAudios с mix_id, необязательными entity_id/options/ref и abort signal; новые объекты добавляются к текущему списку | static. Как SDK-метод отображается в доступный нашему адаптеру endpoint и какие права требуются — не установлено |
| Настройки Микса | Тот же файл, byte 40201: getStreamMixSettings по типу, преобразование серверной конфигурации; byte 5138 — сброс выбранных options и restart | static. Категории/совместимость берутся с сервера; конкретные options нельзя придумывать по рекламному описанию |
| Обратная связь | `32e8bdae.8dbb1ead.js`, byte 73119: ToggleDislike вызывает отдельный dislikesService activate/deactivate; состояние и события отделены от коллекции | static. Сетевой write/read контракт и влияние на выдачу не проверены |
| Подписка артиста | `audioplayer-lib.2bb1cbd4.js`, byte 204247: follow/unfollow через al_artist.php с artist_id/ref/hash и сменой состояния кнопки | static. Доступность action hash и подтверждение серверного состояния в Wave требуют отдельного исследования |
| Подробности плейлиста | `audio.e07a1ce1.js`, byte 93373: create/edit отправляет title/description/no_discover/audio_ids; отдельный путь обложки — byte 93859 | static. Сохранение description/no_discover частично уже есть в нашем сетевом адаптере; UI редактора описания отсутствует |
| Готовый каталог/подборки | Публичная страница содержит MusicTrackRow и MusicPlaylistItem; анонимный DOM получен после controlled navigation/wait | public runtime только чтения. Наличие публичных карточек не доказывает доступность персональных подборок |

Ресурсы получены с объявленных страницей URL вида `https://st.vk.ru/dist/web/chunks/<имя>`; audio — `https://st.vk.ru/dist/web/audio.e07a1ce1.js`. Пример идентичности: c7995f35 SHA-256 `5dc3292d2fe5d5358fc9db5e996ed04c4a07e882db0669426574e2c28b4396c3`; audioplayer-lib — `b63cea642bd30688a7c4e0d0145f24257b01503a652aba520eafd8278902892a`. Полный локальный provenance содержит URL/размер/хеш каждой выбранной копии. Публичные ресурсы могут меняться, хеш важнее имени функции.

VK официально описывает настраиваемый Микс, жанры, редакционные/алгоритмические подборки и микс по своей коллекции: [обновления 2025](https://vk.company.ru/ru/press/releases/12125/). В [отчёте за I квартал 2026](https://vk.company.ru/ru/investors/info/12312/) перечислены настроения/занятия, «Похоже на прослушанное», «Микс по артистам» и плавные переходы. Это полезные направления; мы не переносим маркетинговые показатели в цели Wave и не считаем все мобильные функции доступными через desktop API.

## Решение для версий

Рекомендуемая основная тема **1.2 — открытие музыки через реально доступные механизмы VK**. Это сильнее продолжает нынешнюю оболочку, чем очередное добавление уже имеющихся настроек. Независимые 1.1.x — ссылки, описание плейлиста, дискография, расширение главной, встроенные MP3-теги; подписки — только после подтверждения VK.

Собственные локальные папки — следующий крупный кандидат, а не маленький пункт «добавить импорт» рядом с радио. Для них нужны local ID, отдельная модель метаданных, сканирование, изменение путей и автономные списки; нынешний local-media proxy сам по себе этого не решает. Нормализация, полноценная статистика и гарантированное gapless тоже не сводятся к переключателю.

Не возвращаем отложенные владельцем next queue, диалог дубликатов и боковые фильтры. Не копируем Spotify Connect/Blend/DJ или серверные рекомендации как будто они доступны вместе с внешним видом. Чужие JS, локализация, графика и ключи не входят в Wave; самостоятельная реализация не называется строгой clean room после чтения поставляемого кода.
