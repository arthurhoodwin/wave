# Разработка и форки Wave

Этот документ — для запуска из исходников, изменения приложения и выпуска своего форка. Описание приложения — в [README.md](README.md), пользовательская инструкция — в [USER-GUIDE.md](docs/USER-GUIDE.md).

## Текущий результат

**Wave 1.1.5 Stable** опубликована как [Latest](https://github.com/arthurhoodwin/wave/releases/latest) и установлена на основном ПК. Границы проверки — [VALIDATION.md](docs/VALIDATION.md). Действующие договорённости и карта документов — [STRUCTURE.md](docs/STRUCTURE.md); дизайн-код — [DESIGN-SYSTEM.md](docs/DESIGN-SYSTEM.md), архитектура/данные — [TECHNICAL.md](docs/TECHNICAL.md). История Alpha/Beta не является текущим списком незавершённых задач.

## Запуск

Проект использует Node.js 24, npm и Windows x64. Версии Electron и зависимостей закреплены в package-lock.json. Команды выполняются из корня репозитория.

```powershell
git clone https://github.com/arthurhoodwin/wave.git
cd wave
npm ci
npm test
npm run test:updates-electron
npm run test:artists-electron
npm run test:discovery-electron
npm start
```

Если пакет Electron установился без исполняемого файла: `node node_modules/electron/install.js`.

`npm start` открывает официальное окно входа VK в отдельном профиле Wave. Не используйте производственный профиль для тестовых сборок с отладочными портами. Автоматические тесты обходятся без аккаунта и настоящей музыки.

## Устройство

```text
Renderer: интерфейс и HTMLAudio / Hls.js
         │ ограниченные команды IPC
Preload  │
         ▼
Electron main
 ├─ VK-адаптер и планировщик запросов
 ├─ метаданные и личная медиатека
 ├─ менеджер загрузок и проверка файлов
 ├─ localhost-прокси сетевого и локального аудио
 └─ Windows: трей, мини-плеер, таймер и обновления
```

- `src/main/` — точка сборки, сетевой адаптер, коллекция, хранилища, воспроизведение и Windows. Подсистемы скачивания, обновлений и текстов выделены в `downloads/`, `updates/`, `lyrics/`.
- `src/preload/` — разрешённые команды между renderer и main.
- `src/renderer/` — интерфейс, тексты, стили и аудиоэлементы.
- `tests/` — Node test runner, синтетические ответы и временные файлы.
- `scripts/`, `build/` — сборка, подпись пакета обновления и установщик.
- [STRUCTURE.md](docs/STRUCTURE.md) — полная карта каталогов и порядок релиза.

Сеанс VK и токены находятся в main/его отдельной сессии. Renderer получает непрозрачный временный localhost-адрес аудио. Метаданные и личный индекс шифруются средствами Windows; сами скачанные аудиофайлы не шифруются. Форматы и ограничения — в [плане скачивания](docs/DOWNLOADS-PLAN.md).

## Перед запуском своего форка

В текущем коде часть имён и путей задана явно. Изменение одного `package.json.name` **не изолирует** форк от официальной Wave.

1. В `package.json` задайте свои name, productName, appId, названия ярлыков, установщика и адреса проекта.
2. В `src/main/main.cjs` измените профиль `wave-vk-research-client`, AppUserModelID и путь резервных установщиков. Выберите отдельный профиль **до первого запуска**, чтобы тестовая сборка не использовала существующий сеанс и данные Wave.
3. Проверьте пути `Wave/installers` в `build/windows/installer.nsh`, названия окон, иконки и видимые строки интерфейса. [Поиск исходников](src) поможет найти оставшиеся значения.
4. В `src/main/updates/github-updater.cjs` и `scripts/release.cjs` замените GitHub-репозиторий и ограничения допустимых адресов. Чужой сервер нельзя добавлять только на стороне renderer.
5. Для собственного обновления используйте собственную пару ключей: открытый ключ — `build/update-public.pem`, идентификатор продукта — `src/main/updates/update-manager.cjs`. Закрытый ключ не входит в репозиторий, сборку или скриншоты. Пакет форка с другим ключом не станет официальным обновлением установленной Wave.
6. Сохраните сведения об исходном проекте и сторонних компонентах. Лицензия исходников — [GPL-3.0-only](LICENSE); условия распространения находятся в самом файле лицензии.

## Проверка изменений

```powershell
npm test
npm run test:updates-electron
npm run test:artists-electron
npm run test:discovery-electron
```

Для сетевого адаптера нужны тесты разных ответов, обрывов и смены аккаунта. Не повторяйте запись после неоднозначного результата: сначала прочитайте состояние. Ошибка формата подтверждения сама по себе не доказывает, что запись не выполнена. [Разбор лайка](docs/VK-OWNERSHIP.md).

Для интерфейса проверяйте реальные клики, Tab/Space/Escape, длинные названия, узкое окно, масштаб 200% и prefers-reduced-motion. Общая палитра и правила — [DESIGN-SYSTEM.md](docs/DESIGN-SYSTEM.md). Не создавайте обязательную очередь перед запуском песни.

Тесты сгруппированы по подсистемам; правила, границы покрытия и результаты аудита — в [TESTING.md](docs/TESTING.md). Актуальное число проверок показывает `npm test`. Их прохождение не заменяет работу на разных компьютерах и проверку настоящих ответов VK. CI выполняет установку зависимостей, Node.js-тесты и отдельный ASAR-прогон в настоящем Electron на Windows. Последний нельзя заменить обычным Node: он должен учитывать виртуализацию app.asar и выход процесса перед заменой файлов.

## Сборка и публикация

```powershell
npm run dist
```

Установщик появится в `dist/`. Официального закрытого ключа для обычной сборки не требуется. Подготовка подписанного `.waveupdate`, контрольных сумм и отката описана в [UPDATES.md](docs/UPDATES.md).

Публичную версию задаёт `package.json.releaseVersion`, npm-версию — `version`, Windows FileVersion — `build.buildVersion`. Меняйте их согласованно с именем артефакта. Windows принимает четыре числовые части; npm требует SemVer. Для предварительных выпусков используется `releaseChannel: alpha`, `beta` или `rc`; они не заменяют стабильный GitHub Latest.

В дереве хранится один файл заметок текущего выпуска — `releases/LATEST.md`. После подготовки артефактов:

```powershell
npm run release:check
npm run release -- --draft
```

Скрипт публикации требует существующий отправленный тег. Проверьте CI, комплект файлов релиза (EXE, подписанный пакет от заявленной точной основы и SHA256SUMS.txt), подпись и установку перед публикацией. Не включайте в Git профиль Electron, cookies, токены, аудиофайлы, подписанные CDN-ссылки и ключи. Правила PR — [CONTRIBUTING.md](CONTRIBUTING.md).

Файловые патчи, разовый переход через EXE и очистка `dist/` описаны в [UPDATES.md](docs/UPDATES.md). Устаревшие локальные артефакты удаляются командой `npm run artifacts:clean`; распакованную текущую сборку сохраняйте как основу следующего патча.

## Быстрый рабочий цикл

Практический порядок — в [AGENTS.md](AGENTS.md), замеры и причины задержек — в [PERFORMANCE.md](docs/PERFORMANCE.md). Для итерации запускайте конкретный файл `node --test tests/<подсистема>.test.cjs`; перед итогом один полный `npm test`. Electron-гейты выбирайте по затронутому поведению, для релиза — один итоговый комплект. Финальный EXE собирается после стабилизации кода/пакетных метаданных, а не после каждого изменения документации.

`npm run release -- --draft` можно безопасно повторить после сетевой ошибки: совпавшие assets проверяются и пропускаются, передаётся недостающее. Загрузка одного файла ограничена5минутами; `WAVE_RELEASE_UPLOAD_TIMEOUT_MS` меняет этот предел при необходимости. Публичный релиз скрипт не перезаписывает. `release:check` завершается ошибкой, если отсутствуют файлы или не совпадают суммы.
